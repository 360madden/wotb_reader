## Key findings

1. **Delta-compare is verified wired end-to-end** — no new product code needed:
   ApiContracts `OffsetCompareRequest.DeltaTarget/DeltaTolerance` → Host.Web
   `GameApiEndpoints` (finite/non-negative validation, delta-only-with-delta)
   → `GameSessionCoordinator` → `MemoryScanEngine.PassesDelta`, which keeps
   candidates where `|Δvalue − target| ≤ tolerance` for Float/Double/Int32/
   UInt32/Int64/UInt64. Covered by `GameApiEndpointsTests` and
   `UltimateScannerUnitTests`. The snapshot API accepts `valueKind: Float`
   (valueSize 4, alignment 4).
2. **Extractor evidence (11.19.0 medvedkovo, session `019fb86c-…`):** tick rate
   confirmed at 1,000,000 ticks/sec (median sample dt ≈ 1s; session span
   2,784.6s == `duration_ticks`/1e6). Auto-selected the most-moving
   participant (the viewpoint is stationary — median 1s displacement 0.0).
   For a 4s window: **2,779 window measurements, median 2D displacement
   0.6935 m/4s, p90 3.1927, max 6.1432** → recommended
   `-CompareMode delta -DeltaTarget 0.6935 -DeltaTolerance 2.4992
   -ValueKind Float` (replayTime variant: `-DeltaTarget 4.0`).
3. **First extractor iteration was degenerate** (2 measurements) because the
   pair filter required ≥80% of a 4s window between consecutive ~1s samples;
   fixed with sliding-window interpolation (binary search + lerp) → dense,
   usable stats.
