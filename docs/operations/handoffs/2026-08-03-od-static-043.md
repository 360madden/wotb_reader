## Key findings

1. **`0x03B7E198` is the DAVA `AnyFn` invoker vtable table.** 34 entries,
   modal target stride `0x2C` (44-byte vtables; 24 entries at that pitch, 9
   irregular), 24/34 named — all `StaticAnyFnInvoker<lambda>` vtables whose
   lambdas bind `TankComponent`/`AimingPointComponent`/`Scene`/`Entity` =
   **component event subscriptions, NOT gameplay roots**. All 24 named
   entries share the same first-slot dispatcher fn `0x002C4550` (24/24).
   Each named vtable has **exactly 1 `.data` root = its own entry in the
   array** (internally-closed set; 0 external roots).
2. **3 `.text` refs decoded** (with the C7/imm32 store fix): constructor
   `mov [esi+0x0C], <table>` at `0x002DF2CB` (object stores the table at
   +0x0C), `mov ecx,<table>` thunk at `0x02B817E1`, and a **runtime patch
   `mov [0x03B7E198], imm32` at `0x03104FAB` that repoints entry[0]** to
   `0x03594958` — the table is mutable (static-initializer-style fixup) but
   holds no gameplay state.
3. **`--vtable-root` cross-correlation:** `GameScene` → 6 matches, primary
   vtable `0x0319D3C4` / COL `0x034A89F0` / **0 data roots**; `TankComponent`
   → 19 matches, every one an `AnyFn` invoker with roots=1 (its array entry).
   Confirms OD-042's vtable-singleton negative for the chain classes.
