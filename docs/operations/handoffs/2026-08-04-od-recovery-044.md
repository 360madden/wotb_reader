## What was done

1. **Full pipeline run #1** (x96dbg launcher): gate green; launcher stayed alive with no window, never spawned x32dbg; rolling hit the 22-round cap at **17 survivors** (plateau, not ≤10); write-trace `FAILED_x64dbg_not_running`.
2. **Fix — x96dbg launcher dropped.** Pre-arm + write-trace resolver now launch `release\x32\x32dbg.exe` directly (game bitness known x86: WOW64-observed, `GuardedMemoryReader` `ImageFileMachineI386`). x32dbg attached 2/2 subsequent runs (pids 49028, 45256).
3. **Run with direct x32dbg:** pre-arm worked; game died at roll round 3 (replay-start flake).
4. **Live finding — harvest gap.** A 2-round roll collapsed to **5 survivors ≤ 10** (tightest yet at the time) but the harvest's fresh increased-compare returned 0 (tail froze between target round and harvest) → empty address file. **Fix:** harvest retry loop (5×2s) — survivors tick every frame during active playback.
5. **Live finding — plateau misread.** Round 9 `increased=0` was treated as "target 0" (0 ≤ 10). **Fix:** `increased=0` is a value-bound plateau-stop; keep the last non-zero round's candidates, with a small-set candidate serialization bump so those addresses are actually carried.
6. **Runs 5–7:** three consecutive replay-start flakes (gate green → `Denied` within ~90s; `onLeaveWorld` → `become hidden` → `OnBackground` ~2s after `LoadGameScene`, no crash dump). ~50% flake rate for the session.
7. **Final run:** full pipeline proven end-to-end; converged to **1 survivor**.
8. **Artifact analysis — the critical finding.** The survivor was **`0x7FFE0010` = `KUSER_SHARED_DATA.SystemTime`** — a FILETIME-style value on the shared kernel page that ticks every 100ns. The game field stopped ticking mid-roll (death signature: 47→44→1), and the always-ticking kernel clock is the last "increased" Double in a dying process. **Kernel writes to that page never fire user-mode hardware breakpoints, so write-BP hits there are 0 by construction** — the mechanism was not the failure.
9. **Fix — KUSER drop.** The roll driver now drops `0x7FFE0xxx` candidates from the address file and logs `WARN_kuser_clock_dropped`.
