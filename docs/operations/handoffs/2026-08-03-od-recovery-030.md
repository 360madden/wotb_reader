## Game-side crash (attempts 2 and 5) — diagnosed, not our pipeline

Both failed launches shared a signature: launcher logged `OfflineReplayVerified`
(`watch_exit=0`, `post_watch_vs=OfflineReplayVerified`), but the session driver
saw `Denied` from its first poll, and the gate reason read
`evidence.monitor_unhealthy`. Root cause confirmed from the blitz log
(`blitz-logs_20260803123418.txt`):

```
[assert] activeController->GetName() == LobbyControllerNames::LOBBY
File: C:/ba/tc/work/t/client/Classes/Account/AccountController.cpp
Line : 386
```

The game itself asserted right at `Start replay event` — a game-side replay-start
flakiness (~2/6 launches), not a clicker or gate fault. The lifecycle monitor
correctly revoked when the game died. **Operational rule added to the workflow:**
launcher-green + immediate `Denied`/`evidence.monitor_unhealthy` ⇒ relaunch,
don't re-click.
