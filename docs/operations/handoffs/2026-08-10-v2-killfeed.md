# Handoff: V2 kill-feed ticker (HUD)

**Date:** 2026-08-10 · **Status:** Complete (offline) · **Scope:** overlay
HUD + frame API; no live memory work

## What shipped

A persistent kill-feed panel for the W2S HUD, pinned to the bottom-left
corner: newest first, "Killer → Victim  t(s)", up to 8 entries. It's the
persistent counterpart to the transient 2 s death pips — built from the
Destroyed events (found in the prior handoff) plus killer attribution from
the damage stream.

## Attribution rule

For each Destroyed event at or before the frame time, the killer is the
attacker of the victim's **most recent Damage event** within a **3 s
posthumous window** after the destroy marker (real replays attribute the
kill hit slightly late — Oasis 3760571's kill lands ~1.7 s after its
destroy marker). No damage evidence → killer null → rendered as "—"
(environmental kill). Kills are ordered oldest first in the API; the view
model renders newest first.

## Plumbing

- **Core**: `OverlayKill` (victim, killer?, replay time); `OverlayFrame`
  gained a `Kills` list (secondary 4-arg ctor keeps old fixtures valid).
- **Application**: `ReplayFrameSource.BuildKills` (attribution +
  `TryParseAttacker`); projector carries `Kills` through unchanged.
- **API**: `OverlayKillResponse` + endpoint mapping + CLI `overlay-frame`
  `kills` array.
- **View model**: `KillItem` (names resolved from the same frame's tanks;
  out-of-roster ids fall back to "Tank N"; environmental killer "—");
  `BuildKillFeed` rebuilds `KillFeed` each frame, newest first.
- **HUD**: `W2sHudView.BuildKillFeed` renders the stacked list panel.
