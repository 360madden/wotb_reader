## Evidence produced (static, no game process)

Reference-site instruction decode (`--refs`) against the hash-bound 11.19.0.10
binary — the offline equivalent of Find-what-writes:

- **`0x03FA0C74`: 9 .text refs (5 load + 4 store), 0 unclassified.**
  - `A1/A3` `mov eax,[abs]` / `mov [abs],eax` accumulator forms plus `8B/89`
    `mov r32,[m+disp32]` / `mov [m+disp32],r32` (ecx).
  - 3 disjoint code clusters: `0x0005D531/53C` (load+store pair),
    `0x006E52D1/DE/F6` (load+store+store), `0x006E64D1`,
    `0x006F18C1/F1/FC` (load+load+store).
- **`0x03FA012C`: 6 .text refs (2 load + 4 store), 0 unclassified.**
  - All `A1/A3` forms; 2 clusters: `0x005F7BBB/BCE/BDB`,
    `0x00601764/785/792` (each load+store+store).
- **Verdict: both are read-write code-initialized globals** — the store mix
  (A3/89) proves runtime code writes these slots, which a pure compile-time
  constant would never show. Disjoint clusters indicate multi-subsystem
  access, consistent with singleton/state roots.

## Review fixes applied

Code review of the new tool modes found and fixed:
1. ModRM never validated in Layout 2 → added `_modrm_is_mem_disp32` (mod=00
   rm=101 absolute, mod=10 rm≠100 base+disp32; rejects mod=11 register forms
   and SIB). All 15 refs re-verified as genuine disp32 forms, 0 unclassified.
2. 0F-prefixed fall-through misclassification → unrecognized 0F-prefixed
   opcodes now stop as "other" instead of being re-tried as 1-byte opcodes.
3. Dead code in `dump_fields_near` (`base_rva`, `rel()` closure) removed.
4. Relative-offset math corrected to `off - raw_root` (the old formula was
   wrong when the window clamped at file/section bounds).
5. float32/int32 double-counting of small integral values → integral floats
   <100k excluded from the float32 pass.
6. Unnecessary try/except around `struct.unpack_from` removed (bounds are
   pre-verified).
7. Window clamped to the containing section's raw extent so neighbor
   candidates are true same-section bytes.
