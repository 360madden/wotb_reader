## Evidence produced (static, no game process)

The classification correction, against the hash-bound 11.19.0.10 binary:

- **`0x037F3054` is an MSVC EH handler/funclet table, not a vtable:**
  - `.rdata`, first dword `0xFFFFFFFF` (sentinel), then interleaved
    {state/int, `.text` code-ptr} pairs targeting `.text` rva `0x02CF0D70`+
    (`lea r,[ebp+disp]; jmp` cleanup/throw thunks).
  - **113 FuncInfo magic numbers (`0x19930522`) within ±0x2000.**
  - Referenced from **48,609 4-aligned `.data` slots, 0 unaligned** — a
    massively-shared infrastructure pointer, not a singleton.
- **`0x03FA0C74` is NOT a standalone root — it is the `+0x04` member of
  record[1] in a repeating 0x50-byte `.data` record family:**
  - Family base `0x03FA0C20`; template `{0x00404064 (.text member-fn),
    <runtime slot>, 0x037F3054 (.rdata EH table), 0, …}`.
  - `0x03FA0C70 + 4 == 0x03FA0C74` exactly.
  - `{0x00404064, *, 0x037F3054}` template matches **3,565 `.data` slots**.
  - `--record-map 0x03FA0C20,0x50,10` → 10 records mapped, **9
    runtime-initialized slots** (+0x04, +0x08, +0x0C, +0x10, +0x18, +0x28,
    +0x30, +0x44, +0x4C); +0x04 zero in 4/10 records (heterogeneous family).
- **`0x00404064`** is a small member function (member-fn prologue, `this+0x144`
  compare, list ops on `[edi+4]`/`[edi+8]`) shared by every record — likely a
  container/list node helper.
